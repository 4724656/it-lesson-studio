# 数据解密课件视觉试点说明

- 分支：`feat/ppt-humanize`
- 试点范围：仅《数据解密》3 页；不修改 `main`、`muse`，不迁移整套课例。
- 目标：比较同一教学重设计在 Marp 与原生 PPTX 中的实际表现；不预设技术结论。

## 选择的原页与实际诊断

| 原页 | 教学职责 | 原页实际问题 | 试点改法 |
|---|---|---|---|
| 2：今日通关路线图 | 先做什么、再做什么、最后得到什么 | 标题是“路线图”，页面实际是三段纵向文字清单；右半屏空白；`□` 无教学语义；`KHOOR` 没有说明是输入还是结果。 | 改为 `KHOOR → 01 密钥探秘 → 02 变量追踪 → 03 逻辑排雷 → HELLO` 的单一路径。每站只保留动作和可观察成果。 |
| 5：凯撒密码 | 一个概念怎样作用于真实数据 | “定义、公式、口诀、越界”并列，`HELLO → KHOOR` 只是小例子；加/解密关系未形成可见的反向操作。 | 用 `H→K` 等完整 5 组真实变换承担解释；保留 `X→A / Y→B / Z→C` 循环例；明确 `KHOOR −3 → HELLO`。 |
| 6：变量追踪 | 在哪里操作、做什么、怎样判断完成 | 页面给出结果 `plain=HEL`，却没有真实界面、入口、轮次定义、提交位置或成功反馈；静态按钮像可点击控件。 | 明确 PPT 仅导航，真实操作在 HTML 作业；复刻实际 HTML 的初始 `0/5` 状态、两道追踪题与提交按钮；写清第 3 轮答 `plain`、第 5 轮答 `key`、提交后看反馈。 |

## 投影页与教师讲解的边界

- 投影页保留：任务顺序、操作入口、最小真实示例、学生下一步动作、可观察的完成标准。
- 移出投影页：同一规则的重复表述、公式推导细节、每轮口头追问、课堂组织用语。
- 试点不把详细教师话术塞进 PPT；后续若进入正式实现，应在 Markdown 备注或教案中维护。

## 两个实现的共同内容

两版都只实现同一批重设计后的三页：

1. 密文 `KHOOR` 经三站任务得到明文 `HELLO`；
2. `HELLO +3 → KHOOR`，以及 `KHOOR −3 → HELLO`，含循环示例；
3. 用本课 HTML 的真实变量追踪任务流程：初始 `0/5`、单步执行、两道题、提交反馈。

两版的视觉目标相同：单一主角、颜色只标记状态、卡片只用来分组、无教学作用的 emoji/占位图删除。差别只在输出通道：

- Marp：Markdown/CSS 渲染为 PDF/PPTX；
- PptxGenJS：原生文字、节点、箭头和步骤作为可编辑 PPTX 对象生成。

本试点的脚本暂放在 `scripts/ppt-humanize-spike.mjs`，只用于比较，不接入正式课件流水线，也不建立完整双通道。它的源内容来自当前《数据解密》课件和 HTML 作业；后续若采用其中一路，应把结构化页面数据抽到单一的课程数据源，而不能同时维护两份课件正文。

## 产物与渲染验证

生成命令：

```bash
node scripts/ppt-humanize-spike.mjs
```

产物目录：`artifacts/ppt-humanize-spike/`（已被 Git 忽略）。

- `数据解密_Marp改良版_三页.pptx`：Marp 输出；对应 PDF 和 3 张 PNG 预览。
- `数据解密_原生PPTX_三页试点.pptx`：PptxGenJS 输出；使用该最终 PPTX 经 LibreOffice 转 PDF 后得到 3 张 PNG 预览，未以 HTML 截图代替。

原生 PPTX 预览命令：

```bash
soffice --headless --convert-to pdf --outdir artifacts/ppt-humanize-spike/native-render \
  artifacts/ppt-humanize-spike/数据解密_原生PPTX_三页试点.pptx
pdftoppm -png -r 150 \
  artifacts/ppt-humanize-spike/native-render/数据解密_原生PPTX_三页试点.pdf \
  artifacts/ppt-humanize-spike/native-render/native
```

## 编辑性检查

PptxGenJS 版本把标题、任务节点、箭头文字、变量/步骤/检查条件全部创建为原生文本与形状；截图和插画均未作为本试点的关键教学内容。

以下修改应通过修改 `scripts/ppt-humanize-spike.mjs` 的文字常量后重新生成，而不是手工改两套正文：

- 修改任务名称：任务节点的文本框会自适应缩小；短名称不会改变节点位置。
- 增加一个步骤：当前路线是为 3 个节点定宽排版；增加第 4 步需要重排路线组件，因此目前不宣称“自动任意扩展”。
- 替换图片：本试点没有图片依赖；正式版可将实际 HTML 截图作为单独图片区，替换图片不会改变文字/步骤布局。

## 结论口径

本试点只回答三个问题：

1. 学生是否能快速看出页面要解决的问题？
2. 教师是否能直接据此组织讲解或操作？
3. 原生 PPTX 的可编辑性和版式控制，是否换来足以抵偿维护成本的收益？

不以“更现代”“更高级”作为验收标准。若 Marp 版已足够，应停止在 Marp 改良；若原生版在真实编辑和视觉复现中明显更稳，再讨论小范围推广。
