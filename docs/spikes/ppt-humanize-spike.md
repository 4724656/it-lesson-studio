# 数据解密课件视觉试点：结论与证据

- 状态：**Spike 已完成；不合入任何 PptxGenJS 代码或依赖。**
- 范围：八年级《数据解密》3 页（任务路线、概念解释、操作练习）。
- 基线：当前 Marp 课件的实际渲染页。

## 结论

### 决定：继续使用 Marp，暂缓引入 PptxGenJS

三页重设计后，改良 Marp 已经达到本轮可接受的静态投影效果：任务路径、密码变换和浏览器操作导航均能用页面结构表达教学关系。原生 PPTX 的确带来可编辑文本/形状，但试点证明它需要维护固定几何坐标和独立页面实现；对于当前“Markdown 同源、可批量生成”的项目，这个维护成本没有换来足以覆盖双通道复杂度的收益。

因此本分支只保留两类可复用成果：

1. Marp 的课堂关系组件：`.task-route`、`.task-node`、`.task-link`、`.browser-guide`、`.code-chip`；
2. Skill 的生成规则：一页一个视觉主角、关系决定版式、颜色标记状态、操作页不伪装为可点击应用。

PptxGenJS 的实验脚本、依赖和生成产物均不进入共享分支。

## 三页实际诊断与改法

| 原页 | 原页问题 | Marp 改法 | 教学收益 |
|---|---|---|---|
| 任务路线 | “路线图”实际是三段文字列表；`KHOOR` 的角色不清。 | `KHOOR（密文输入）→ 01 密钥探秘 → 02 变量追踪 → 03 逻辑排雷 → HELLO（明文）`。 | 学生一眼看到从输入到成果的顺序。 |
| 概念解释 | 规则、公式、口诀并列；真实变换不突出。 | 对齐显示 `HELLO +3 → KHOOR`、`KHOOR −3 → HELLO`，并将 `X→A / Y→B / Z→C` 作为循环例。 | 图示承担“同一密钥大小、方向相反”的解释，不要求学生从段落中提炼规则。 |
| 操作练习 | 静态按钮像能点击；没有明确说明在哪里做、做什么、何时完成。 | `.browser-guide` 明确“PPT 只负责导航”；展示 HTML 作业真实的初始 `0/5`、单步执行、两题追踪和提交反馈。 | 学生知道在浏览器操作：第 3 轮答 `plain`，第 5 轮答 `key`，提交并看反馈。 |

## 验证记录

改良 Marp 三页已实际生成 PDF、PPTX 和 PNG 预览；原生 PPTX 仅作为比较证据，由最终 PPTX 经 LibreOffice 转 PDF 后渲染预览，不作为项目交付物。

本地生成命令（仅用于复查 Spike，不作为正式流水线）：

```bash
node scripts/ppt-humanize-spike.mjs
```

最终正式路线不依赖该命令，继续使用：

```bash
node scripts/export-lesson.mjs <课程目录>
```

## 后续落地规则

- 新课件优先选用关系组件，而不是默认堆叠 `.card`。
- 只有天然对比才用双栏；路径、过程和操作各用对应组件。
- 操作页截图、链接或二维码由实际课堂入口决定；静态 PPT 不得模拟可运行按钮。
- 每次主题/组件变更后，必须输出 PDF/PNG 并检查投影可读性与关系表达。
