## P0：真实实现与风险

已核对 AGENTS.md、主 Skill、output-spec.md、ai.js、server.js、check_lesson.py、base-template.html 和 CI/镜像工作流。

- 当前生成器是两次非流式 API 请求，第一阶段写三件套，第二阶段写完整 HTML。server.js 的“流式”注释与实现不一致。
- 主 Skill 全量注入两阶段；公共 CSS 通过字符串注入 HTML 提示词。base-template.html 有可复用能力，但尚未成为运行时组装器。
- 原 API 封装丢弃 finish_reason/usage，没有截断识别。解析器可接受缺件、覆盖重复标记，写入前没有阶段完整性检查。
- check_lesson.py 已有内联 JS 语法检查，无需重复建设。
- 原 sanitizeGeneratedClassworkHtml 会裁剪正文、删除额外屏幕、移除多余 hands-on/data-prose 标记，并插入隐藏自评文本。这些行为可能掩盖教学缺失。P1 保留兼容路径，增加修正前后独立审计，不能据修正后的通过率宣称原始生成质量提升。
- getGradeLimits 仍硬编码 output-spec.md 数值，提示词还把“上限”写成“严格数量”。P1 不修改这些教学策略；P2/P3 应统一从规范读取。
- Docker 自动发布由 main/tag/release 或手动触发，普通开发分支提交不会发布生产镜像。

修改前基线：`npm test` 14/14；两个已有 Python 回归脚本通过；`uv run python scripts/check_lesson.py examples/` 为 0 错误 / 0 提醒。Python 测试是独立脚本，不能用 unittest discovery 的“0 tests”当作通过证据。

## P1：默认关闭，可回退

在服务环境设置 `AI_GENERATION_DIAGNOSTICS=1`，重启服务后开启。删除变量或设为 `0`，重启后恢复原 V1 生成路径。无需数据库迁移；提示词、温度、API 请求体、调用顺序均未调整，无新重试或拆分调用。

开启时：

1. 每次 API 请求在任务目录追加 `generation-diagnostics.jsonl`：开始时间、模型、HTTP 状态、finish_reason、提供方实际 prompt/completion/total tokens、耗时与状态。缺失用量/结束原因用 null 表示，不估算。仅提取白名单字段，不记录密钥、消息、教材、图片、模型响应正文或服务端错误正文。模型名仍为配置值。
2. length/max_tokens/content_filter、空内容、缺失/重复/非法文件标记及明显缺尾的 HTML，在本阶段文件写入前报错。没有自动续写或重试，不为通过检查补标记。第一阶段成功文稿在第二阶段失败时保留；第二阶段截断不会覆盖目标目录原有 HTML。
3. 修正前、修正后分别调用现有 `check_lesson.py`，记录错误/提醒数量及内容是否被旧修正器改变。审计失败标记 unavailable；它不是检查通过。P1 的语法/教学门禁审计仅记录，不据此修复或拒绝交付，旧修正器仍有上述已知风险。
4. 审计使用临时文件并清理，每次子进程上限 20 秒，最多两次，未增加模型请求。诊断落盘失败仅给出通用告警，不使成功响应失败。启用后可能增加本地检查耗时，API elapsedMs 不包含审计时间。
5. check_lesson.py 增加文档 html/head/body 边界与 script/style/section 起止数量检查；HTMLParser 避免把脚本字符串和注释中的标签当成真实标签。这是独立 CLI 检查增强，未设置开关时也适用，但不会修改 HTML。不是完整 HTML 解析验证或浏览器行为证明。

诊断 JSONL 不会进入现有只筛选四件最终交付文件的 ZIP。可以在服务器任务工作目录查看，未添加管理界面或下载端点。
