## 一、教材分析
本课是浙江教育版小学信息科技六年级上册第一单元《算法的实现》第5课。教材依托课本第18~23页，承接前序算法抽象与代码编写基础，引导学生将设计的算法部署到计算机中运行。教材以经典“鸡兔同笼”问题为核心情境，首先通过在 Python IDLE 环境中打开并运行程序，直观感知计算机执行算法的高速与精准；接着以“调试程序”为突破口，系统呈现变量大小写混淆、中文全角符号、缩进层级缺失三大典型错误与排查方法；最后针对“参数无解时程序无输出”这一缺陷，引导学生引入状态跟踪变量 `jie` 完善算法流程与代码，体会算法健壮性与通用性的计算思维内涵。

## 二、学情分析
六年级学生在前几课已初步了解 Python 基本语法与三大控制结构，并完成了鸡兔同笼初版代码。但在上机实践时，学生容易出现“见红报错就慌张、不会看错误行号、中文全角标点屡现、缩进层级混乱”等典型问题。且学生对算法理解多停留在“特定数字能算出来即可”，缺乏对异常情况的健壮性考量。  
针对六年级学生认知特点，本课搭建三大实战支架：
- **生活通俗比喻**：将计算机执行算法比作“严谨的高铁调度员按轨道全速推进”，将报错提示比作“代码发出的精准求救信号”，将状态变量 `jie` 比作“答题卡上的通关信号灯”；
- **真实启发设问**：通过“人算满头大汗为何计算机只要0.01秒”、“参数改后控制台毫无反应是死机了吗”等问题链驱动探究；
- **避坑预警锦囊**：传授调试三看口诀——看拼写大小写、查半角英文冒号、数Tab与4个空格缩进。

## 三、教学目标
- **信息意识**：通过上机运行算法，感受计算机处理复杂问题的高效精准，树立“用程序语言赋能问题解决”的数字化工具意识。
- **计算思维**：通过排查 NameError、SyntaxError 与 IndentationError，掌握依报错提示定位调试的方法；通过引入状态变量处理无解情况，体会算法必须具有输出的确定性与逻辑完整性。
- **数字化学习与创新**：熟练在 Python IDLE 中开展打开、运行、调试与修改，积极利用单文件互动课件进行仿真验证，提升数字化探究纠错能力。
- **信息社会责任**：理解代码规范性对程序稳定运行的重要性，养成良好的代码书写习惯与机房文明操作守则。

## 四、教学重点
在 Python IDLE 环境中规范运行程序；理解循环结构 `while` 的执行机制；排查变量大小写、中英文标点、代码缩进等常见报错。

## 五、教学难点
根据 Python 错误回溯信息精确定位错误根源并修复；理解并运用状态跟踪变量完善算法中的无解分支。

## 六、教学过程

| 教学环节 | 教师活动 (含设问·比喻·支架·点拨) | 学生活动 (一人一机) | 设计意图 |
|:------------ |:------------------------------------------------ |:--------------------------------- |:------------------- |
| **一、情境激趣<br />复习导入<br />(4分钟)** | 1. **情境回顾**：出示《孙子算经》“鸡兔同笼”名题（35头，94足）。<br />2. **启发设问**：“上节课我们已把算法写成 Python 代码。但若不通电、不执行，代码只是一串字符。如何让计算机真正动起来，帮我们秒出答案？”<br />3. **揭示课题**：板书课题《第5课 算法的执行》。 | 1. 回顾上一节课编写的鸡兔同笼枚举代码。<br />2. 思考代码与程序执行的关系，明确本课上机见证算法运转的目标。 | 从前序课时自然过渡，明确“编写”到“执行”的飞跃。 |
| **二、初试锋芒<br />运行程序初探<br />(8分钟)** | 1. **示范程序运行规范步骤**：<br />- 启动 Python IDLE 编辑器；<br />- 【File】➔【Open】打开桌面的 `鸡兔同笼.py`；<br />- 在窗口点击【Run】➔【Run Module】（或按快捷键 <kbd>F5</kbd>）。<br />2. **比喻点拨**：计算机执行算法就像“高铁调度员”，按既定代码轨道全速精准执行，毫秒间完成36次循环验证。<br />3. **组织学生上机运行**，观察输出：`23 只鸡， 12 只兔。`<br />4. **指导完成导学单第一关**。 | 1. 打开 IDLE，规范载入 `鸡兔同笼.py`。<br />2. 按 <kbd>F5</kbd> 运行，观察输出结果。<br />3. 对比口算与机算速度，体会计算机执行的高速准确。<br />4. 独立完成导学单第一关记录。 | 建立规范的 Python 上机流程，让学生体会算法落地的成就感。 |
| **三、代码侦探<br />排查三大卡点<br />(10分钟)** | 1. **设置悬念**：下发 3 个故意埋雷的代码文件，学生运行纷纷弹出红色报错！<br />2. **化解焦虑**：“报错不是失败，而是计算机在给你发精确求救信号！”<br />3. **拆解三大经典卡点**：<br />- **卡点①：大小写混淆**（`while Tu < 36:`）➔ `NameError`。点拨：Python 严格区分大小写，`tu` 与 `Tu` 是两个不同变量；<br />- **卡点②：中文标点冒号**（`while tu < 36：`）➔ `SyntaxError`。点拨：所有语法标点必须在英文半角状态下输入；<br />- **卡点③：缩进层级丢失**（`ji = 35 - tu` 未缩进）➔ `IndentationError`。点拨：Python 用冒号和缩进标识从属关系，缩进是代码的骨架。<br />4. **避坑锦囊**：“运行前先看三处：拼写大小写、英文半角冒号、Tab缩进”。指导完成导学单第二关。 | 1. 运行带错程序，观察控制台弹出的错误提示行号与类型。<br />2. 化身“代码小侦探”，根据老师支架对照分析，逐个修复 3 处典型 Bug。<br />3. 归纳调试规律，掌握根据错误信息定位修复的技能。<br />4. 完成导学单第二关侦探纠错表。 | 直击日常编程最高频痛点，变被动报错为主动调试，培养计算思维。 |
| **四、逻辑再造<br />完善算法分支<br />(12分钟)** | 1. **发起挑战**：“若笼子里有 35 个头、93 只脚，答案是多少？”<br />2. **学生上机修改运行**：修改参数后运行，控制台一片空白，什么都没输出！<br />3. **引发冲突**：“算法的基本特征是什么？必须有输出！空白一片让用户以为死机了，这符合好算法要求吗？”<br />4. **引出状态跟踪变量 `jie`**：<br />- 状态变量 `jie` 就像一盏通关信号灯。初始为 0（代表还没找到解）；<br />- 一旦满足条件算出答案，顺手把灯点亮为 1（`jie = 1`）；<br />- 循环 36 次结束后查验：如果 `jie == 0`，就打印 `此题无解`！<br />5. **对比出示课本 P22 流程图与 P23 代码**，组织学生补全无解分支。 | 1. 修改总脚数为 93 运行，亲身体验控制台毫无反应的尴尬局面。<br />2. 理解“算法必须有明确输出”的科学准则。<br />3. 学习引入状态变量 `jie` 的方法，在循环外初始化、循环内标记、循环后双向判断。<br />4. 上机输入健壮性代码，成功打印“此题无解”，完成导学单第三关。 | 从语法正确上升到算法逻辑健壮性，提升算法设计的全面性。 |
| **五、全课小结<br />数字素养升华<br />(6分钟)** | 1. **梳理认知进阶**：从“自动化执行”到“调试三大卡点”，再到“状态变量完善逻辑”。<br />2. **高阶思维**：好的算法能解决同一类问题。若每次改代码太繁琐，下节课我们将学习如何接受键盘动态输入！<br />3. **组织实操通关作业**：打开桌面《05_算法的执行_课堂作业.html》答题自评并导出 `.txt` 学习凭单。<br />4. **常规整理**：指导工位规范整理与文明关机。 | 1. 师生共同复盘本课核心概念与调试口诀。<br />2. 思考算法的通用性价值。<br />3. 在 HTML 作业中完成答题自评，一键下载学习凭单。<br />4. 规范关机，键盘推入桌下，椅子归位。 | 形成教学大闭环，由点及面升华计算思维，抓实机房好习惯。 |
